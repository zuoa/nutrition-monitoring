# 组织用户与食堂管理员

## 操作入口

- 系统管理员在侧栏的“组织用户”进入 `/users`；系统设置原有的“用户与组织”页签也使用同一管理界面。
- 列表显示姓名、登录名、角色、部门和状态，可按姓名或登录名搜索，按部门（含下级）、角色、状态筛选并分页。
- 新增用户时填写姓名、唯一登录名、8–128 位初始密码与角色；部门可选。
- 编辑支持修改资料、角色、部门、启停状态和密码。新密码留空时保留原密码。
- 删除沿用原有的账号停用机制，保留历史关联；在“已停用”筛选中编辑并勾选“允许此用户登录”即可恢复。
- 当前管理员不能删除、停用自己或取消自己的管理员角色。停用账号的原登录令牌立即无法继续访问接口。
- 钉钉用户未设置本地登录名时显示“未设置（钉钉登录）”；设置登录名时须同时设置密码。组织同步仍可更新这类用户的姓名和部门。

## 食堂管理员工作台

登录后的默认页面是 `/menus`，桌面侧栏与手机底部导航只提供“每日菜单”和“菜品库”。手动输入其他页面地址会返回每日菜单。

菜单页通过菜品元数据接口读取餐次，无需访问系统配置。可复制前一天的各餐次菜单、调整选择后保存；复制会过滤已停用菜品。菜单和菜品页提供相互跳转入口。

菜品页保留新增、编辑、删除、价格和营养信息、样图上传与裁剪。导入和批量操作默认折叠，样图状态以是否上传展示。混淆体检、样图向量重建和模型细节只向系统管理员展示。

后端根据数据库中的当前用户角色限制食堂管理员，只允许认证、菜单和菜品接口；消费、报告、学生、视频分析、系统配置等接口返回 403。

## 接口

以下用户接口均仅限系统管理员：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/admin/users` | 用户列表；支持 `search`、`role`、`dept_id`、`include_descendants`、`active_only`、`status`、`page`、`page_size` |
| `POST /api/v1/admin/users` | 创建账号，成功返回 201 |
| `PUT /api/v1/admin/users/:id` | 编辑账号；只变更提供的字段 |
| `DELETE /api/v1/admin/users/:id` | 停用账号 |

创建的必填字段为 `name`、`username`、`password`、`role`。创建与编辑可选 `dept_id`、`is_active`；编辑继续支持原有管理范围字段。`dept_name` 根据所选部门确定。返回值增加 `has_password` 布尔值，始终不返回密码及其哈希。

停用用户查询使用 `active_only=false&status=inactive`；查看全部状态使用 `active_only=false`。停用账号的登录名仍保留，不能重复创建。

新增 `GET /api/v1/dishes/tasks/:id`，仅允许系统管理员和食堂管理员读取菜品 ZIP 导入、批量营养分析的任务进度。视频和其他任务 ID 返回 404，菜品页面不再依赖视频分析任务接口。

本次没有数据库结构或环境变量变更。
