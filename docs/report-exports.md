# 学生营养报告与图片导出

个人报告的网页预览和 PNG 使用同一个后端 HTML/CSS 模板。底图位于
`backend/app/templates/reports/background.svg`，替换此文件即可调整头部和边缘装饰；
模板和底图在进程内缓存，修改后需重启 API 和 Celery worker。

网页预览通过带版本参数的字体 URL 复用浏览器缓存，不在报告请求中裁剪字体。
字体资源公开缓存一年，文件更新后 URL 随之变化；PNG 导出继续内嵌裁剪后的字体。
前端按学生或组织、报告类型和周期缓存最多 20 份结果，有效期 60 秒，并合并同时发起的相同请求。
点击“刷新”、提交报告生成或推送后会清空缓存；切换登录账号也会清空缓存。

## 使用

- “个人报告”新增“详细报告 / 简要报告”切换，默认保留原有详细版本。两种版本共用现有报告快照，不重新生成或覆盖报告。
- 简要报告按五个区块展示核心指标、达标评价、营养搭配比例、就餐特征和下期建议；支持周报、月报、单份 PNG 及全班 ZIP。批量导出可单独选择版本。
- 简报展示能量、蛋白质、碳水、膳食纤维、脂肪、钙六项指标；钙显示日均营养供给（mg / 天），缺失时显示“—”。钙仅展示，不计入评级；营养达标评价沿用原有五项指标的年龄、性别参考评级，仅展示 A—D 等级及评价文字，不展示分值或分数进度。资料不足时显示“待评价”。
  结构合理性与特征使用已有营养素状态；早餐仅呈现记录次数，不据此认定达标。没有独立分类支持的水果、奶豆类、油炸频次不作推断。
- 简报使用参考图中直接裁切的校舍、植物和营养图标，资源见 `backend/app/templates/reports/assets/`。校徽仅用于名称匹配的学校，其他组织保留自身名称。
- 在“营养报告 → 个人报告”选择学生，点击“下载 PNG”。图片宽 1600px，高度随完整内容变化。
- 切换“周报 / 月报”，选择指定周或月份查看历史报告；点击“最新周报 / 最新月报”返回最新报告。
- 管理员可生成当前层级（个人、班级、年级、校区）的周报或月报，按所选周期批量生成。未选择周期时，生成上一完整周或上一自然月。
- 周报只统计所选 ISO 周的周一至周五，周六、周日不计入营养汇总、就餐次数和趋势；支持跨年周。月报覆盖所选自然月，包含闰年二月。
- 已生成的周一至周日周报为历史快照，需选择对应周重新生成，才能使用周一至周五的统计口径。
- 点击“批量导出”，选择班级及已有周报或月报周期，提交后查看进度并下载 ZIP。导出类型跟随页面上的周报 / 月报选择。
- 班级导出采用当前在籍、启用的学生名单。每名学生只取所选类型、起止日期完全一致的最新个人报告，不自动生成缺失报告。
- ZIP 内包含每人的 PNG 和 UTF-8 BOM 编码的 `导出清单.csv`；缺失报告或个别渲染失败会列入清单。
- 任务 ID 按当前用户保存在浏览器，刷新后恢复最后一次任务。产物保留 24 小时，过期需重新导出。

## 部署

重新构建后端镜像以安装 `pypdfium2` 和中文字体、Pango 依赖。API、通用 Celery worker
必须挂载同一私有目录；两个 Compose 文件已添加
`${DATA_DIR:-./data}/report_exports:/data/report_exports`。

月报功能新增 `class_monthly` 和 `campus_monthly` 枚举值，已有数据库需先运行 `make migrate`
（生产环境使用 `make prod-migrate`），再重启 API 和 Celery worker。

学生年龄与出生日期字段由迁移 `20261018_0030` 添加，上线前同样需要执行迁移。

`REPORT_EXPORT_STORAGE_PATH` 默认 `/data/report_exports`，可覆盖为本地可写目录。
本地运行 API 和 worker 时须配置相同路径；Docker 内修改路径时也要同步调整挂载目标。
此目录不能配置成 Nginx 公开静态目录。Celery beat 每小时清理过期产物，并将超过两小时仍未完成的任务标记失败。
API、worker、beat 都需要运行。单份 PNG 同步返回；班级导出使用 `maintenance` 队列，任务上限为 30 分钟。

## 数据与接口

个人报告读取会补充 `content.meal_statistics`，包含 `meal_count` 和 `breakfast_count`。
最新报告与详情还返回 `content.presentation_html`（详细版）及 `content.brief_presentation_html`（简要版），供禁用脚本的 iframe 预览；报告列表不携带 HTML。
存储的原始消费、识别、日汇总与历史报告不被改写；尚未包含补全版本的新版个人报告在读取或导出时补全展示数据。

旧版个人报告次数仍查询已关联的负金额消费；新版报告合并消费、已匹配/人工确认的学生餐盘和明确餐段的营养记录。
消费遵循启用的消费地点范围，按应用时区、当前餐段配置归类，同一天同一餐段去重；餐段外记录单列，不增加就餐次数。
原始营养日均仍按有效记录日统计；报告直接呈现日均营养供给结果，计算方法仅保留在技术文档中。班级任务开始时批量读取统计，导出期间使用该批数据。

## 按餐次折算全天供给

新版生成的个人和群体报告增加 `content.meal_projection`，网页预览与 PNG 使用同一份计算结果。
个人预览、PNG 和群体报告统一展示最终日均营养供给，不展示原始值对照、餐次权重、公式、计算举例或样本处理细节。
未包含 `meal_projection` 的旧版快照仍展示已有在校膳食日均值；已有估算结果缺失的指标显示“—”，不回退混用原始值。
历史报告为生成时的快照；尚无补全版本的新版个人报告会在读取、PNG 或批量导出时补充餐次与营养估算。
新生成报告保存完成后的快照，后续数据到达不自动改写该快照。旧版个人报告与已有群体报告可重新生成以使用完整的新分析。

早餐、午餐、晚餐的默认份额为 **25%、40%、35%**，合计100%。依据
[《学生餐营养指南》WS/T 554—2017 第3.3节](https://www.moe.gov.cn/jyb_xwfb/xw_zt/moe_357/s6211/s6329/s6366/201712/W020171226542698597687.pdf)，
三餐能量和营养素的份额范围分别为25%～30%、35%～40%、30%～35%；所选默认值位于对应范围内。
标准给出的是配餐份额，按此反推全天是本系统采用的估算假设，不是指南规定的实际摄入测量方法。

- 单餐：仅午餐800 kcal，全天折算为 `800 / 0.4 = 2000 kcal`。
- 多餐：早午餐合计除以0.65，午晚餐合计除以0.75，三餐齐全除以1。
- 多天：每项分别按 `有效餐次营养量总和 / 对应份额总和` 计算，不先平均原始日均再除以统一份额。
- 群体：先计算每名学生的周期折算量，再按学生等权汇总；样本人数按营养素单独统计。
- 份额分母只使用该营养素数据完整的餐次（包括满足样本条件的营养补全）；未能补全营养、餐段未归类的记录不增加分母。
  同一餐有多个餐盘时，先合并所有餐盘；其中缺失的营养素不将部分合计视作完整一餐。
- 每日营养日志在JSON内保存 `_quality_version: 3`、按餐段合并的 `_meals`，不涉及数据库结构变更。
  重新生成时优先从原始匹配与识别记录重建旧日汇总的餐次快照，不改写历史日汇总。
  无原始识别可追溯时，仅接受餐次明确、无未知餐段的v2完整汇总；其他数据不参与折算。

全天折算假设未记录餐次与已记录餐次具有相同营养供给水平。奶类、水果等在不同餐次分布可能不同，
折算值不代表全天实际摄入。生成报告后仍沿用现有推送流程。

## 缺失就餐记录与营养补全

补全版本为 `meal_statistics.completion_version: 1`。个人、班级、年级和校区生成时使用同一批处理逻辑：

- 先合并独立证据：负金额消费、已匹配/人工确认的学生餐盘、明确餐段的营养记录；
  无需同时具备消费与识别。空营养字段不否定已有就餐证据，不能确定学生身份的图片不用于补次数。
- 对仍无证据的餐次，观察此前56天的工作日或周末习惯；至少8个同类有效就餐日。
  个体就餐概率采用 `(有该餐的天数 + 1) / (有效天数 + 2)`。同一天还须有另一餐的直接证据。
- 只有个体习惯概率至少85%、同班当天至少5名其他学生有就餐迹象、至少8个历史同类日提供稳定参照，
  并且班级该餐出现显著记录下降时才补次数。使用 `个体概率 × (1 − 当天同班该餐比例 / 历史比例中位数)`，
  达到80%才补记为一餐。概率与来源保留在元数据，不展示算法说明。
- 正常同班采集下的孤立个人空白、经常不吃该餐、整天无在校就餐迹象、历史不足、未完成或未来餐段，
  不自动增加次数。明确配置的当天菜单没有该餐时，也不按采集异常补餐。
  一贯不吃该餐且同班采集正常时标为“未见就餐”；其余无法区分的空白保留未知，不作为营养不足或未吃的直接证据。
  对置信度至少80%的“未见就餐”，营养估算计入该餐的零供给份额，避免全天估算又默认该餐已吃；这不增加次数，也不把缺失营养数据改成零。
- 营养补全只作用于已确认或已达到推定门槛的就餐事件。按营养素优先使用本人此前56天、同类日期、同餐段至少3餐的中位数；
  不足时使用同班当天同餐段至少3名其他学生；仍不足时使用此前14天同类日期同餐段至少5餐、3名其他学生的中位数。
  不跨餐段借值，不使用未来数据或估算结果再次训练；真实零值保留，样本不足时不编造数值。
- 统计分别保留 `observed_count`、`estimated_count`、`nutrition_estimated_count` 和每餐来源；
  网页及PNG只展示最终次数、营养结果和必要的“预计就餐”标记。所有估算仅用于报告，不写入原始消费或日营养日志。

该算法区分有证据的记录恢复与基于习惯的估算；学校缺少请假、校外就餐与主动不吃的明确记录时，无法保证逐餐确认真实进食。

## 展示指标与学生达标等级

详细版个人预览、PNG 与群体报告展示能量、蛋白质、脂肪、胆固醇、碳水化合物、膳食纤维六项；简报将胆固醇替换为钙。
营养趋势为能量、蛋白质、脂肪。其他营养数据继续在服务内部保存，不影响识别与历史数据。

学生管理、名单导入支持可选的 `birth_date`（YYYY-MM-DD）和 `age`（1—120整数）。
参考年龄依次取报告结束日期时的周岁、填写的年龄、年级对应年龄；年级参考会在报告中标注。
小学一至六年级对应6—11岁，初中一至三年级对应12—14岁，高中一至三年级对应15—17岁。
不明年级、缺少性别或实际年龄超出6—17岁时不强行匹配。外部名单同步保留这两个本地字段；
旧导入文件缺少这两列或为空时，不清除已有值。新报告保存参考资料快照，历史报告缺少快照时读取补充。

单项参考依据 WS/T 554—2017 表1及续表：能量为年龄、性别参考值的90%—110%，蛋白质为80%—120%，
脂肪占能量20%—30%，碳水化合物占50%—65%；脂肪、碳水的克数范围使用同一最终能量结果表达。
膳食纤维以年龄组20g或25g为下限。胆固醇保留数值，不设置该标准未规定的学生阈值，不计入评级。

五项参考指标齐全时，使用连续评分给出报告等级，不按达标项数分级。各项区间内计100分，
区间外按距离最近边界的相对偏离幅度 `d` 评分：`100 × (1 − min(d / 0.5, 1)²)`。
偏离边界1%、5%、10%、20%时，单项分别约为99.96、99、96、84分；偏离达到50%时计0分。
膳食纤维仅评价低于下限的偏离，高于下限不扣分。

单项权重为能量30%、蛋白质25%、脂肪20%、碳水化合物15%、膳食纤维10%。
综合分为 `加权均值 × (0.5 + 最低单项分 / 200)`，在保留权重差异的同时，
让最弱项的偏离程度连续影响整体平衡，避免单项严重偏离被其他指标完全抵消。
综合分保留一位小数后分级：90分及以上为A（达标良好），
75—89.9为B（基本达标），60—74.9为C（需改善），低于60为D（重点关注）。
区间外偏离不超过10%标注“轻微偏低/偏高”，超过30%标注“明显偏低/偏高”，中间标注“偏低/偏高”。
这是系统的膳食参考评分，不是标准规定的健康诊断等级；评分版本为 `nutrition_assessment.version: 2`。
`passed_count` 仅保留为兼容统计，不参与评分。简报展示等级、评价文字和单项状态，不展示综合分；公式与权重仅保留在技术文档。
资料不足、缺少全天估算结果或任一参考指标缺失时显示“待评价”；真实零值仍参与单项判断。
参考图以绿色区间和棕色竖线分别表示参考范围与学生最终结果，网页及PNG使用同一模板。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/reports/student/<student_id>/latest` | 可传 `type=personal_weekly/personal_monthly`、`period=YYYY-Www/YYYY-MM`；不传周期返回该类型最新报告 |
| `GET /api/v1/reports/<scope>/<scope_id>/latest` | scope 为 class/grade/campus；type 对应 `<scope>_weekly/monthly`，period 同上 |
| `GET /api/v1/reports/fonts/<name>` | 公开的预览字体，仅允许内置的四个 WOFF2 文件，支持 ETag 条件请求 |
| `POST /api/v1/reports/generate` | 传入 `type` 和 `period`，或完整周期的 `period_start`、`period_end`；仅管理员可用 |
| `GET /api/v1/reports/<report_id>/export.png` | 下载个人报告 PNG；可传 `format=detailed/brief`，默认 detailed |
| `GET /api/v1/reports/class/<class_id>/export-periods` | type 为 personal_weekly（默认）或 personal_monthly，获取对应个人报告周期 |
| `POST /api/v1/reports/class/<class_id>/exports` | 传入 `type`（默认 personal_weekly）、`period_start`、`period_end`、可选 `format=detailed/brief`（默认 detailed），创建任务，返回 HTTP 202 |
| `GET /api/v1/reports/exports/<task_id>` | 查询状态、进度及下载是否可用 |
| `GET /api/v1/reports/exports/<task_id>/download` | 下载 ZIP，过期返回 HTTP 410 |

个人下载沿用学生报告权限。班级导出仅开放给管理员和管理该班级的教师、年级负责人；
任务状态、下载同时校验申请人和当前班级权限。其他用户即使知道任务 ID 也无法下载。
